# Skill 创作质量准则

生成的 Skill 应在描述中区分触发场景，在正文中给出可验证结果，而不是泛化的助手承诺。
保留用户目标、输入、输出、约束、风险、授权边界和离线验证步骤。必要时添加最小的
reference、script、asset 或测试资源，并在正文中明确其用途。

优先明确性：只询问仍缺失的一项要求；不要臆测权限、目标目录、敏感数据范围或外部
副作用。把执行性操作放在明确授权之后。若任务只需要说明，生成指令而不是脚本。

资源必须局限在包内，文件名不能是绝对路径或含路径遍历。正文必须保持一个规范
`SKILL.md`，不要复制同一工作流到多个宿主适配器。完成后使用离线验证器检查，再让用户
审阅生成的文件树与版本控制差异。
